# 训练、评测与实现细节

## 1. 动作头到底改了什么

旧项目的 NAVSIM 标注为 8×3，但 π0.5 模型动作空间仍为 32 维。新项目的加噪、flow matching 目标、动作 token embedding、输出投影和采样都直接使用 8×3。

```text
F0 / L0 / R0 当前图像
    → 共享 SigLIP ViT → 共享 projector → 768 个图像 tokens
当前 ego state + recorded command → 最长 64 个文本 tokens
    → Gemma VLM prefix ──────────────┐
8×3 噪声轨迹 → 新 action_in_proj ────┤ 18 层联合 attention
时间 t → 预训练 time MLP → AdaRMSNorm │
    → 预训练 Gemma 动作专家 → 新 action_out_proj → 8×3 flow velocity
```

在训练中，对训练集归一化后的轨迹 `a` 和标准高斯噪声 `ε`：

```text
t ~ 0.001 + 0.999 × Beta(1.5, 1)
x_t = t ε + (1-t) a
target velocity = ε-a
loss = mean((vθ(x_t, t, images, prompt) - (ε-a))²)
```

采样从 `t=1` 的高斯噪声积分到 `t=0`，默认 10 个 Euler 步。prefix KV 在每次采样中只计算一次，供全部去噪步骤复用。输出反归一化后是相对于**当前帧**的未来位姿，不是逐步位移增量、方向盘角度、速度指令或 32 维占位动作。heading 最后归一到 `[-π, π)`。

当前使用预训练动作专家，仅重新初始化两个输入/输出线性层。机器人动作前三维没有明确的驾驶语义对应，所以不把旧投影的前三列/行直接视为驾驶头。若要比较“整个动作专家随机初始化”，需要另建消融配置，当前默认不这样做。

## 2. 全参训练和 DDP 的细节

所有保留参数均 `requires_grad=True`，默认第 1 epoch 用 no_grad 冻结 ViT，随后解冻；projector、VLM、动作专家和新动作头全程更新。注册的参数集合不变，兼容 DDP 的阶段切换。也可配置全程全参或全程冻结 ViT 对照。不要缓存视觉特征；`cache_data.py` 缓存的是像素和输入 tokens。完整日程见 [80GB 训练方案](80GB训练方案.md)。

π0.5 的 prefix 不能注意 suffix，因此**最后一层 prefix 的输出投影/FFN，以及最终 prefix norm，不影响动作损失**。这些继承参数保留以兼容基础权重，但跳过无用的最后 prefix FFN 计算；不能要求每个继承参数都必须有非零梯度。DDP 使用 `find_unused_parameters=True` 处理这些计算图末端；CPU DDP 测试包含这一情况。动作专家不使用词表 embedding 和 lm_head，后者已直接移除。

模型参数、梯度、AdamW 一阶和二阶矩都保留 FP32。BF16 仅用于 autocast 的计算。这样小学习率更新不会因为 BF16 参数的舍入而消失。默认 VLM/projector/动作专家峰值 LR 为 `1e-5`，ViT 为 `1e-6`，新动作投影为 `1e-4`，使用 warmup + cosine 和梯度裁剪；这些是可调起点，不代表 NAVSIM 上的最优超参数。

`checkpointing` 可选：

| 值 | 含义 |
|---|---|
| `none` | 不重计算，激活显存最多，通常有吞吐优势，需实测 |
| `vision` | 只对 ViT 层重计算 |
| `full` | ViT 与联合 transformer 每层重计算；初始默认 |

没有旧实现中“强制打开重计算”或在逐层外再次 checkpoint 整个模型的嵌套。`torch.compile` 默认关闭，开启后首次编译较慢，需把 warmup 与稳态吞吐分开测量。SDPA 的具体 CUDA kernel 由 PyTorch 根据形状、dtype 和 mask 选择，不保证所有场景都走 FlashAttention kernel。

DDP 默认 FP32 梯度通信，不宣称已实现 BF16 通信压缩或 ZeRO。使用 `gradient_as_bucket_view=True` 减少稳定状态下的梯度副本。网络带宽不足时，增加梯度累积可减少同步频率，但需维持合理有效 batch。

## 3. 当前数据和新机器的数据

导入的清单沿用旧项目的自定义 recording-disjoint train/val，不是官方排行榜 navtrain/navtest 的完整筛选复刻。已检查训练/验证 token、原始 recording 和图像路径互不重叠，并对数据根目录中的 46 个测试 recording 做排除检查。归一化只从训练集重新计算。

本机清单图像路径示例：

```text
sensor_blobs/trainval/<log>/CAM_F0/<image>.jpg
```

新机器只需改 `configs/sft_80gb.yaml` 的 `data.root`。`root` 下应存在 `sensor_blobs` 与 `navsim_logs`。不要把统计文件换成机器人预训练归一化统计。

如果只有代码和原始 NAVSIM 数据：

```bash
python scripts/prepare_data.py --root /your/navsim \
  --source-split trainval --stride 4 --output assets/navsim --check-images
```

该命令读取本地可信 pickle 日志，按原始 recording 的 SHA256 固定 80%/20% 拆分，每隔 4 帧取一个当前锚点。它仅从当前帧读取相机、速度/加速度、记录的导航命令；未来位姿只用于标签。过滤时间不连续样本。`test` 日志只读取文件名以排除 recording，不读取测试标签构造训练统计。

若需要保持旧项目精确划分：

```bash
python scripts/prepare_data.py --root /your/navsim \
  --from-manifests /your/old/assets/navsim_trainval --output assets/navsim
```

工具拒绝覆盖已有清单，也拒绝 train/val/test recording 泄漏。要比较新的划分，请使用新输出目录和新训练实验。

## 4. 训练命令与续训

所有命令在项目根目录、已激活的独立环境下执行。训练脚本不会自动挑选所谓“空闲 GPU”，由 `CUDA_VISIBLE_DEVICES` 和 `NPROC_PER_NODE` 显式指定。

多节点使用标准 torchrun 环境变量，每台服务器运行一次，例如两台各 8 卡：

```bash
# 第一台 NODE_RANK=0，第二台 NODE_RANK=1；MASTER_ADDR 为第一台可达 IP
NNODES=2 NODE_RANK=0 MASTER_ADDR=10.0.0.10 MASTER_PORT=29500 \
  NPROC_PER_NODE=8 bash scripts/train.sh --set train.output=runs/two_nodes
```

多节点的代码/数据应相同，rank 0 写检查点。各节点续训时都需要能读取同一份 checkpoint，可使用共享目录或显式复制完整检查点。NCCL 多节点网络性能尚未实测。

续训只接受带 `COMPLETE` 标记的 checkpoint；保存先写 `.partial` 目录，完成后重命名。训练状态包括优化器、scheduler、各 rank RNG、epoch、下一个 batch 索引；中断后加载相同配置可恢复数据顺序。数据集不使用随机几何增强，DataLoader 具有独立 generator，不因重新创建迭代器消耗 flow matching 的随机序列。CUDA 算子的逐位确定性不作保证。

如果想换 world size 或有效 batch，作为新实验使用模型权重起步，不要混淆为完全相同的续训。当前 CLI 的 `init_checkpoint` 默认按基础模型加载并重置动作投影；**不要把训练好的 NAVSIM checkpoint 填入该字段来期待保留动作头**。相同配置恢复使用 `--resume`；更改训练规模时使用 `--warm-start <checkpoint>`，保留已训动作头、重建优化器和日程，并使用新输出目录和相同归一化统计。

## 5. 验证与官方 NAVSIM Agent

`scripts/evaluate.py` 在验证集逐样本以 token 派生固定 seed，输出 `predictions.jsonl` 和 `metrics.json`。固定 seed 和 ODE 步数便于比较。ADE/FDE 不能替代碰撞、路权、舒适度等官方评估。

可直接调用部署 API：

```python
from navpi.policy import NavPiPolicy

policy = NavPiPolicy("runs/navsim_full_sft/step_00001000", device="cuda")
trajectory = policy.predict(
    images={"cam_front_center": front_rgb, "cam_front_left": left_rgb,
            "cam_front_right": right_rgb},
    state=[speed, vx, vy, ax, ay],
    prompt="Drive safely. Recorded navigation command: 0 1 0 0",
    seed=42,
)
assert trajectory.shape == (8, 3)
```

图像数组应为 RGB uint8。命令必须来自数据中的 recorded command，不能根据未来标签推断。

`navpi.navsim_agent.NavPiAgent` 实现了 NAVSIM v1 的 `initialize`、`get_sensor_config` 和 `compute_trajectory`。只加载历史中的最后一帧三路相机，返回 `Trajectory(poses, TrajectorySampling(time_horizon=4, interval_length=.5))`。`configs/navsim_agent.yaml` 可复制进你安装的 NAVSIM 的 Hydra agent 配置目录，修改绝对 checkpoint 路径，再使用该 NAVSIM 版本原有的官方 scoring 命令。NAVSIM、nuPlan、地图与 metric cache 由评测环境提供，不强行混入本项目训练依赖。

完整官方 navtest 输入准备、批量预测与独立 CPU PDM 脚本命令见 [NAVSIM 适配](NAVSIM适配.md)。接口按本机 `AutoVLA/navsim` 的 v1 dataclass 核对；尚未运行真实 PDM、NAVSIM v2 EPDMS 或 GPU agent 推理。不要把 CPU 模型测试视为官方评测通过。

## 6. 发给别人

代码包是可独立安装的 Python 项目，不需要复制整个 `openpi_old`。基础权重包需另行传输；GitHub 普通 Git 不包含本机大文件。完整传输包可以包含 checkpoint、tokenizer、清单和统计，但不包含原始 NAVSIM 图像，也不包含正在进行的训练结果。

收件人应先：安装独立环境 → 核对 checkpoint SHA256 → 修改数据根目录 → CPU 检查 → 在目标 GPU 空闲时跑短测/调 batch → 正式训练。这里的顺序是运行说明，本次未启动后面的 GPU 工作。
