# 80GB 全参 SFT 方案

## ViT 和 projector 怎么处理

三路图像分别通过同一个预训练 SigLIP，再通过共享 projector；拼接顺序是 F0、L0、R0。改动作维度只需要重建动作输入/输出投影。**ViT 和 projector 都保留原结构与预训练权重。** 224×224 letterbox 保持几何比例，但远处小目标可能损失细节。更高分辨率需要位置编码适配、训练与显存验证，不是直接改一个尺寸参数。

这里默认采用分阶段训练，是针对约 3 万训练样本、新动作投影随机初始化、机器人到驾驶的领域变化所做的工程起点，尚未由本项目真实训练证明最优：

| 模块 | 第 1 epoch | 第 2～20 epoch | 峰值学习率 |
|---|---|---|---|
| ViT | 冻结，eval + no_grad | 全部解冻，独立 warmup 50 steps | `1e-6` |
| projector | 全参训练 | 全参训练 | `1e-5` |
| VLM | 全参训练 | 全参训练 | `1e-5` |
| 动作专家、时间 MLP | 全参训练 | 全参训练 | `1e-5` |
| 新 3D 输入/输出投影 | 全参训练 | 全参训练 | `1e-4` |

projector 只有约 236 万参数，承担视觉到语言空间的适配，默认没有必要冻结。ViT 约 4.12 亿参数，完全冻结可节省反向计算和优化器状态，但可能限制驾驶视觉适应；全程同大学习率更新则可能破坏预训练表示。默认先冻结再低学习率解冻，是这两种需求的折中。

[OpenVLA 的视觉消融](https://arxiv.org/html/2406.09246v3#A4.SS3) 在其机器人任务中观察到微调视觉编码器优于冻结；不能直接把该结果当作 NAVSIM 结论。[AutoVLA 附录 D.3](https://arxiv.org/html/2506.13757v2#A4.SS3) 的冻结视觉设置属于 RFT，并配合 LoRA，也不能等同于这里从基础 π0.5 开始的 SFT。

推荐先跑默认方案，再做同数据划分、相同有效 batch、相同训练预算的冻结对照。若解冻后验证 ADE/FDE 和验证 PDM 恶化，可减小 ViT LR 到 `3e-7`，或选冻结方案；若改超参数，使用新输出目录。不能用 navtest 反复选训练设置。

```bash
# 全程冻结 ViT；projector 等仍训练，这个对照不称为全模型全参训练
NPROC_PER_NODE=8 bash scripts/train.sh --set train.vision_mode=frozen \
  --set train.output=runs/frozen_vit

# 从第一步全参训练，ViT 仍使用较小 LR
NPROC_PER_NODE=8 bash scripts/train.sh --set train.vision_mode=full \
  --set train.output=runs/full_vit
```

冻结通过 ViT 前向 no_grad 实现；参数保留在相同 optimizer/DDP 注册集合中，冻结阶段梯度为 None，AdamW 不执行更新和 weight decay。解冻后立即建立视觉梯度与 Adam 状态，无需重新构造 DDP。最后一层 prefix 不影响动作的计算图末端除外，这些继承参数不产生梯度，不代表主动冻结 VLM。已用两进程 CPU DDP 验证切换逻辑。

## 训练多少 epoch

默认 **完整 20 epochs：1 epoch 视觉冻结 + 19 epochs 完整微调**。此前 8 epochs 是保守的试跑预算，没有本项目收敛证据支持它是正式训练的最佳轮数；现按至少 20 epochs 的要求增加预算。20 epochs 也不保证收敛或最优，应同时检查训练损失、验证 ADE/FDE 和验证 PDM。

每 epoch 使用完整验证集、10 步 flow 采样和固定 token seed 计算 ADE/FDE/heading。记录 `validation.jsonl`；ADE 改善超过 0.001m 时更新 `best.json`。默认 `early_stop_patience=0` 关闭早停，`min_epochs=20`，`max_steps=null`，不会因验证平台期在第 20 epoch 前退出。`best.json` 指向该选择规则下的 checkpoint，不一定是最后一个；记录早期最佳模型与完整训练 20 轮并不冲突。

若需要更多预算，在启动前用 `--set train.epochs=30` 设置完整 30 轮；需要“至少 20 轮、最多 30 轮”的早停实验，可显式加 `--set train.epochs=30 --set train.min_epochs=20 --set train.early_stop_patience=5`。中途改总 epoch 会改变 cosine 日程，不能算精确 resume；已有 8-epoch 配置的训练 checkpoint 应用原配置恢复，或用 `--warm-start` 开新实验，后者是额外训练的新日程。本次只修改新项目的默认配置，不修改正在运行的训练。

快速排错可显式 `--set train.max_steps=20 --set train.validation=false`，这是用户主动设置的短测例外，会在 20 次更新后退出，不能称为完成 20 epochs。本次没有执行。SFT、验证误差和 PDM 的区别，以及验证集 PDM 比较命令见 [SFT 目标与相关工作](SFT目标与相关工作.md)。

默认 5% global warmup + cosine 到峰值 LR 的 10%；ViT 从解冻时开始单独 warmup/cosine。AdamW β=(0.9,0.95)，weight decay=0.01，梯度范数裁剪=1.0。参数和 moments 为 FP32，计算用 BF16，不使用 GradScaler。

有效 batch = 卡数 × 每卡 micro batch × 累积次数。建议第一组实验固定 64：

| GPU 数 | micro batch | grad_accum | 有效 batch |
|---:|---:|---:|---:|
| 1 | 2 | 32 | 64 |
| 2 | 2 | 16 | 64 |
| 4 | 2 | 8 | 64 |
| 8 | 2 | 4 | 64 |

按当前 30,266 训练样本、8 卡、micro batch 2、累积 4：DDP 每 rank 去掉余数后 3,783 个样本，DataLoader drop_last 后 1,891 个 microbatches；每 epoch `ceil(1891/4)=473` 次优化器更新，20 epochs 共 9,460 次，30 epochs 共 14,190 次。20 轮日程的 5% global warmup 为 473 次，ViT 解冻后仍使用独立 50 次 warmup。末尾短累积窗口按实际窗口大小缩放 loss。完整自定义数据重建后的样本数可能不同，应以启动日志为准。

20 个完整 checkpoint 的磁盘预算约 760GiB，建议预留 800GiB 以上；30 个约 1,140GiB，另计基础权重、像素缓存和评测输出。当前保存策略不自动删除历史模型。

## 80GB 显存预算和调速

3.35B 参数按 FP32 参数 + 梯度 + 两个 Adam moments 估算约 50GiB 静态内存上界；未参与损失的末端参数没有梯度/moments，因此实值可能略低。额外需要 BF16 autocast 副本、激活、DDP bucket、NCCL 和 CUDA 工作区。80GB GPU 的实际可见 GiB 以硬件报告为准。普通 DDP 不拆分参数或优化器，每卡都要装下整个模型。

初始配置每卡 batch 2、`checkpointing=full`，不是实测容量承诺。已有优化包括三路相机、原生 8×3 轨迹、相机合批、SDPA、fused AdamW、局部 KV cache 推理、uint8 SSD 缓存、异步传输、逐层非 reentrant 重计算、累积期间 no_sync，以及 gradient bucket view。

`cache_data.py` 缓存 resize 后像素和 tokens/targets，不缓存 ViT 特征，因此兼容全参视觉训练。30,266 / 7,569 样本像素约 12.7 / 3.2GiB。预取 worker 按每 rank 计算，8 卡默认 32 个 workers；CPU 或磁盘紧张时降至每 rank 2，不是越多越快。

调优流程：

1. 先用完整解冻模型测 `full`、`vision`、`none` 重计算，以及 batch 1/2/4/8；默认保留 74GiB reserved 上限，可按实际卡容量调小。
2. 候选包含至少 6 个真实优化器步骤，排除前 2 步，再按 samples/s 选择。第一次完整更新必须包含 Adam 状态分配，不能只测前向显存。进一步稳定测量可设 `--steps 20`。
3. 调优工具每个候选新进程，OOM 后停止继续增大该模式 batch；其他错误立即报告。生成 `recommendation.json`、`recommended.yaml` 和各候选日志。
4. 生成配置自动按 target batch 调整累积；不能整除时向上取整并打印实际 batch。例：8 卡 batch 4，累积 2，仍为 64。
5. 再做正式训练。验证含多步采样，保存每份约 38GiB；epoch 总耗时必须额外计入验证和磁盘写入。调优 samples/s 只代表训练窗口，不是端到端 epoch 速度。

```bash
python scripts/tune_batch.py --gpus 8 --batches 1 2 4 8 \
  --checkpointing full vision none --steps 20 --target-batch 64 \
  --memory-budget-gib 74 --set data.train_cache=data_cache/train \
  --set data.val_cache=data_cache/val --output runs/tuning_final
```

冻结 ViT 的实验可用 `--vision-mode frozen` 单独测量，但不能把冻结期大 batch 直接沿用到需要解冻的实验。`torch.compile` 默认关闭，固定 batch 后另开测量；编译耗时和遇到阶段切换的重新编译需计入取舍。SDPA 并不保证所有 mask/形状都采用 FlashAttention kernel。

如果连 full 重计算、micro batch 1 都无法放入，检查其他进程占用后，再另做 FSDP/ZeRO 或不同优化器状态方案；本仓库目前只实现 DDP，不宣称有这些功能。不要为了满足“全参”而偷偷冻结模块，也不要为了“用满”增加无收益的缓存。

## 续训与复现

`--resume` 恢复完整模型/optimizer/scheduler/每 rank RNG/epoch/batch 位置及验证早停状态；要求原 world size、batch、学习率日程和数据哈希一致。`--warm-start` 保留 NAVSIM 头，重建 optimizer/scheduler，适合换卡数、batch、总轮数；必须沿用 checkpoint 的归一化统计。新目录避免混入旧日志。不要把已训 NAVSIM 权重填入 `init_checkpoint`，该字段按基础权重读取并重置动作头。

多节点每台分别运行，例如 2 节点×8 卡；第二台改 `NODE_RANK=1`：

```bash
NNODES=2 NODE_RANK=0 MASTER_ADDR=10.0.0.10 MASTER_PORT=29500 \
  NPROC_PER_NODE=8 bash scripts/train.sh --set train.grad_accum=2 \
  --set train.output=runs/two_nodes
```

各节点须使用相同代码、数据，且能读取同一份恢复 checkpoint。rank 0 保存；CUDA 与 NCCL 完整训练/恢复、多节点扩展尚未实际测试。CPU 检查范围见 [检查记录](检查记录.md)。
